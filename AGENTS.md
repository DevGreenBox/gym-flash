# Personal Flash — рабочие правила

Именные флешки с гравировкой для художественной гимнастики.
Бриф заказчика — в [CLAUDE.md](CLAUDE.md), он главнее этого файла.
Дизайн-система — в [docs/design-system.md](docs/design-system.md).

Стек: Next.js 16 (App Router, Turbopack), React 19, TypeScript, Tailwind CSS 4,
pnpm. Сервера у проекта нет: корзина живёт в `localStorage`, формы замоканы.

## Что нельзя выдумывать

- **Цены, объём памяти, сроки, отзывы, любые цифры про компанию.** Их нам не
  давали. На сайте стоит «уточняется», в коде — `TODO(client)` в `lib/site.ts`.
- **Фотографии.** На сайте их нет вообще: вместо каждой стоит серый экран
  `components/placeholder.tsx` с подписью, чего не хватает. Стоки и рендеры
  запрещены. Исходники заказчика — в `assets/`.
- **Тексты разделов.** Взяты из `assets/реф.pdf` дословно, лежат в
  `lib/content.ts`. Где в макете стоит «Какой то текст» — там `null`
  и честная строка «текст уточняется», а не наше сочинение.
- **Цвета корпуса.** Сняты глазом с фотографии, точные значения анодирования
  должен прислать заказчик.
- **Шрифт гравировки.** На производстве Segoe Print Bold, на сайте Caveat Bold:
  у оригинала нет веб-лицензии. Заменять только вместе с лицензией.
- **Логотип.** Оригинал — `assets/logo-original.jpg`. На сайте пересобран в
  `components/logo.tsx`: красный заменён на цвет выбранной флешки.

Флаги `FORMS_ARE_MOCKED` и `PRICES_ARE_UNKNOWN` в `lib/site.ts`. Перед запуском
снять их, подключить приём заявок и убрать `robots: { index: false }`
из `app/layout.tsx`.

## Где что лежит

- `app/` — маршруты: главная, десять разделов из меню заказчика и `/cart`
- `components/` — компоненты; `components/section-page.tsx` — шаблон раздела
- `lib/site.ts` — контакты, меню, цвета, размеры; `lib/content.ts` — тексты
- `lib/cart.ts` — корзина в `localStorage`; `lib/engraving.ts` — позиции
  конструктора там же, с проверкой при чтении и отменой удаления
- `docs/` — дизайн-система; `assets/` — исходники заказчика, наружу не идут

## Правила

- Токены — в `app/globals.css`. Второго акцентного цвета нет: единственный цвет
  на экране — `--brand`, цвет выбранной флешки. Его выставляет клиентский
  компонент на `:root`, шапка и подвал наследуют.
- Флешка — снимок базовой модели плюс гравировка вектором поверх
  (`components/flash-drive.tsx`). Металл, цепочка, карабин и кольцо взяты
  из растра; цвет корпуса кладётся режимом `multiply` через маску пластины,
  надпись рисуется в SVG с viewBox в миллиметрах — координаты те же, что
  на чертеже: пластина 49,96 мм, поле текста 33,42 мм, поле знака 11,50 мм.
- Ассеты флешки собирает `python3 scripts/prepare-drive.py` из
  `assets/drive-source.png`: обрезает, приводит колпачок к реальной доле
  (17 % длины пластины), режет два варианта — с подвеской и без — и пишет
  координаты пластины в `lib/drive-measures.json`. Руками файлы
  в `public/drive/` не правим, правим скрипт.
- `chain={false}` — вариант без подвески: для миниатюр, где цепочка съедает
  ширину (корзина, ряд комплекта, плитки галереи, превью направлений).
- Анимации делает браузер: появление секций — `animation-timeline: view()`
  под `@supports` и `prefers-reduced-motion`. Контент виден и без анимации.
- Свойства в анимациях только `opacity`, `transform`, `color`, `background`.
- Иконки — из `components/icons.tsx`. Эмодзи и типографские стрелки (`→`, `×`)
  в разметке запрещены: разнобой толщин выдаёт шаблон.
- Одно выделение на элемент: рамка **или** заливка **или** тень.
- Миллиметры печатаем через `mm()` — запятая, два знака, как на чертеже.
- Где в кадре должен быть товар — рисуем его вектором (`FlashDrive`),
  а не ставим серый экран: флешка у нас векторная и ждать фотографа незачем.
  Серый экран остаётся там, где нужна живая съёмка: гимнастка, мастерская,
  упаковка, рекомендательные письма.
- Демонстрационные фамилии в галерее и превью подписаны как демонстрационные.
  Выдавать их за выполненные заказы нельзя.

## Кто за что отвечает

Проект разрезан на шесть агентов в `.claude/agents/`. Границы жёсткие:
пересекаться им нельзя, иначе правила начнут спорить друг с другом.

| Агент | Отвечает | Не трогает |
|---|---|---|
| `project-manager` | бриф, `TODO(client)`, решения, распределение работы | код и вёрстку |
| `art-director` | композиция, типографика, палитра, движение | логику и данные |
| `frontend-engineer` | страницы, компоненты, состояние, маршруты | флешку и тексты |
| `copywriter` | любой текст на странице и метатеги | вёрстку |
| `product-artist` | флешка, её размеры, ассеты, промты и фотобриф | остальной сайт |
| `qa-engineer` | контраст, клавиатура, семантика, скорость, сборка | дизайн-решения |

Правило разрешения споров: чертёж важнее картинки, текст заказчика важнее
нашей редактуры, замеренная цифра важнее впечатления.

## Накладная и доставка

Сделано честно и наполовину — вторая половина упирается в СДЭК.

- **Накладная заказа** собирается целиком: номер `PF-ГГММДД-NN`, дата,
  стороны, построчная гравировка, подписи. Печатается штатным
  `window.print()`, стили печати — в `globals.css`.
  Это бланк мастерской, а не транспортная накладная СДЭК: та печатается
  из их системы по их API и требует договора.
- **Расчёт доставки** — механизм в `lib/delivery.ts`. Вес флешки, вес
  упаковки и таблица тарифов помечены `TODO(client)` и пусты; пока они
  пусты, расчёт честно отвечает «вес уточняется» или «тариф на этот город
  уточняется». Цифры не выдумываем: заполнится таблица — оживёт расчёт,
  разметку трогать не придётся.

## Как показывать макет

Заказчик открывает сайт через прокси Coder, а не с `localhost`. **Дев-сервер
для показа не годится**: Next блокирует свои dev-ресурсы как запрос с чужого
origin, канал обновления не поднимается, страница остаётся без гидратации —
разметка есть, обработчиков нет, ни одна кнопка не отвечает. Симптом ровно
такой: «конструктор не кликается».

Показываем продакшен-сборку:

```bash
pnpm build && PORT=3007 pnpm start
```

После каждой правки — пересобрать. Хост прокси на всякий случай прописан
в `allowedDevOrigins`, но полагаться на dev при показе не надо.

## Как писать текст

Два признака, по которым текст опознают как машинный.

- **Объяснение того, что и так видно.** Если гравировка меняется на глазах,
  не надо писать «появится сразу». Если рядом семь свотчей, не надо писать
  «цвет можно поменять». Подпись объясняет только то, чего в интерфейсе нет.
- **Оценочные прилагательные.** «Надёжный», «удобный», «качественный»,
  «широкий ассортимент» запрещены. Прилагательное либо измеримо
  (анодированный, металлический, лазерная), либо его нет.

Ещё три правила, из тех же соображений:

- Одна мысль говорится один раз. Если она сказана в заголовке, в подписи
  её не повторяют другими словами.
- Приём «X, а не Y» не используем: он звучит как оправдание.
- Внутренняя кухня наружу не выходит. «Нужен договор со службой и ключ API»,
  «когда заказчик пришлёт съёмку» — это в `TODO(client)` в коде, а не на
  странице. Посетителю говорим «уточняется».
